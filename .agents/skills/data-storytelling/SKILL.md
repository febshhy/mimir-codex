# Data storytelling — audience → evidence → visible decision

**Authority:** Analysis communication and chart reasoning; `$data-statistics` controls numerical claims; `$data-dimensional-modeling` controls measure and grain; `$gui-design-thinking` controls live dashboard interaction and navigation; `$visual-design` controls surface aesthetics; `$content-writing` controls wording.

Read [Knaflic concept extraction](references/KNAFLIC_METHOD.md). For each deliverable:

1. **Context:** identify audience, meeting/use situation, decision, single message and intended action. Mark whether the work explores data or explains a validated finding.
2. **Evidence:** validate population, unit, denominator, period, uncertainty, baselines and caveats with analyst/producer; preserve exact source and freshness.
3. **Chart:** select comparison, time trend, distribution, composition, relationship or geographic form by task. Use tables for exact lookup and charts for patterns. Avoid 3D and distorted axes.
4. **Clutter:** remove meaningless borders, gridlines, redundant legends, noisy color and decoration; retain units, source and material uncertainty.
5. **Attention:** use honest contrast and direct labels to guide a reader; never encode confidence as decorative emphasis. Check grayscale and color-vision accessibility.
6. **Narrative:** headline = evidence-backed takeaway, then context → observation → meaning → recommendation with alternatives/caveats; recommendations are conditional on authority and evidence.
7. **Acceptance:** test one cold reader's interpretation, exact arithmetic, legibility at target viewport, accessible text, interaction states and truthful handling of missing/stale data.

Return a communication brief, validated claim table, chosen chart with rationale, annotation plan and limitations. Do not rewrite exploratory chart findings as causal conclusions. Avoid over-optimizing visuals before data trust is established.
